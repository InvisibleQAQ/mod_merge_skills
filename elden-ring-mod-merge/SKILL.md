# 法环双 Mod 合并

使用本技能的命令行工具完成分析、冲突处理、参数写回与文件组装。自动处理能确定的改动；需要取舍的真实冲突由用户决定。不得以文件覆盖、加载顺序或整行 CSV 导入代替参数合并。

## 输入与范围

开始时核对以下事实；已有信息直接复用，只询问缺失且会改变结果的部分：

- A、B：两个实际 Mod 资源根目录，根下各有 `regulation.bin`；不要把安装器、压缩包或外层发布目录当作资源根。
- C：两者共同基线的 `regulation.bin`、来源及版本。普通 Mod 通常使用同版本原版；大修附属 Mod 使用对应的干净大修底板。文件夹同名、内部版本号相同都不能证明共同祖先。
- 游戏及 Mod 版本、各自必须保留的功能、独立输出目录。
- 可用的 Smithbox release 目录、Python 3.10+ 和 .NET 10 SDK/runtime。源码目录与运行库目录分开识别。
- 可选的 C 资源目录：用于普通文件的三方比较；只给 C 参数文件时，同路径不同普通文件由用户选择。

缺少 C 时仍可盘点资源，但不得把任意 A/B 或 vanilla 当成已经确认的共同基线。首版要求三份参数内部版本相同；不自动升级、降级或混用 PARAMDEF。

本技能暂不处理 `.anibnd[.dcx]`、`.behbnd[.dcx]`、`.hkx[.dcx]`、`.tae[.dcx]`、`.hks[.dcx]` 和 `variablenameid.txt`、`statenameid.txt`、`eventnameid.txt`。其他已识别的动画、行为或映射资源也应记录为范围外，不能因扩展名未知就宣称兼容。工具只内置前述明确规则；发现额外格式先补充排除规则并验证，再组装。

参数 Row ID 用于定位，不属于允许自动重新分配的 ID。双方新增同 ID 的不同内容不能靠改 ID 消除冲突。重复 ID 的修改不得未经行实例匹配就合并。

## 执行

先读 [命令行操作](references/cli.md)，首次搭建或更换 Smithbox 时再读 [工具依据与兼容边界](references/tooling.md)。

1. **预检**：检查输入说明、SHA-256、基线来源和工具版本；确认输出与输入、游戏安装目录分离。构建随附 codec，不修改 Smithbox 源码、不启动 GUI。
2. **分析参数与资源**：用 codec `analyze` 比较 C→A、C→B；用 `merge_assets.py scan` 盘点普通文件和范围外资源。退出码 `2` 表示已生成待决冲突报告，不是成功完成合并；`1` 表示错误，保留原始信息。
3. **自动合并确定项**：仅一方变化保留该方，双方同值去重，同一行不同字段独立合并。删除/修改、双边不同字段值、同 ID 不同新增行等进入冲突。完整规则见 [合并规则与验收](references/merge-contract.md)。
4. **请求冲突决策**：按参数表/Row ID/字段或普通文件路径，给出 C、A、B 值、作用与可核实的影响。可建议来源及理由，但不得擅自批量采用 A/B。用户明确给出的策略可直接执行；不要反复请求已授权决策。首版支持 `base`、`a`、`b` 选择，不支持把两值相加或写入任意手填值。
5. **生成参数**：将用户决策写成绑定输入 hash 的 JSON，执行 codec `build`。无冲突直接生成，不必询问。确认写出、重新解密和计划核验全部成功。
6. **组装**：用 `merge_assets.py assemble` 将已验证参数与已决普通文件写入新的输出目录，生成目录外的收据。范围外资源不纳入输出；不得偷偷选择其中一方充数。
7. **交付**：报告输出路径、输入与输出 hash、自动合并及冲突数、决策、范围外资源、结构验证结果、尚未执行的游戏功能测试。存在范围外依赖时明确标为“本次范围内合并产物”，不得称为整包兼容补丁。

## 关闭条件

- 没有未决参数/文件冲突；未知定义、版本差异或重包错误没有被静默忽略。
- 构建后的参数重新读取通过，实际数据与已决合并计划一致，原始输入未改变。
- 资源复制 hash 与所选来源一致；范围外文件与未测试功能有明确清单。
- 不以“生成了 bin”推断游戏功能正确。游戏测试单列状态；本技能不自动启动游戏、部署到安装目录或改变加载配置。

## 调用示例

> 使用 $elden-ring-mod-merge 合并 A 和 B，基线是 C，Smithbox 在指定目录。先自动合并无冲突项，冲突列给我决定；动画、行为、HKS 和 ID 映射暂不处理。

## 开发验证

维护脚本后，在仓库根运行 `python -m unittest discover -s tests -v`；codec 的构建和回读测试见命令行参考。测试合成数据或复制出的测试数据，不能用修改用户输入来制造冲突。
