# 合并规则与验收

## 参数三方规则

C 为共同基线，A/B 为两份完整参数文件。比较单位为参数表、行、字段；数值 `+` 不具有合并含义。

| C→A / C→B | 结果 |
| --- | --- |
| 都没变 | 保留 C |
| 只有一方变化 | 使用变化的一方，包括有依据的删除 |
| 双方变化结果完全相同 | 保留一份 |
| 同一原有行不同字段变化 | 分别应用到基线行 |
| 同一字段不同变化 | 冲突，选择 `base` / `a` / `b` |
| 一方删除行，另一方修改行 | 行状态冲突，选择完整来源状态 |
| 双方新增不同 ID | 保留两行 |
| 双方新增相同 ID、相同内容 | 去重 |
| 双方新增相同 ID、不同内容 | 整行冲突，不重分配 ID |
| 重复 Row ID 的表发生无法安全对齐的变化 | 保守按工具报告处理，不按 ID 字典静默压缩 |

字段比较保留原始类型、字节数组及浮点精度；浮点不做近似相等。行名与行数据区别处理，但不得丢弃行名变化。工具不推断参数引用或脚本的语义兼容性。

新增行参考其来源中后续仍存在的行定位插入，不一律追加到末尾；已有行重排作为整表冲突处理。双方相同新增行以 A 的位置为准，双方独立新增在同一位置时采用稳定处理顺序。依赖特殊行顺序的 Mod 仍需核对最终顺序。

不认识的参数表、无法解析的参数和容器元数据不能悄悄消失。根据 codec 明确报告阻断，或在可以保持原始条目字节的情况下让用户选择完整来源；不能把无法解析伪装成没有变化。删除参数行与包目录没有某个文件不是同一种语义。

## 普通文件规则

两个 Mod 目录按覆盖包理解：只在 A 或只在 B 出现的文件会保留，缺失不推断为删除。两边同路径同 hash 只复制一次；同路径不同 hash，有 C 文件时按三方规则选择单边变化，否则要求选完整来源。不对未知二进制做文本合并，不拼接压缩容器。

文件决策绑定扫描报告的 SHA-256，组装前重新检查输入清单与 hash。更改输入后重新分析，不复用旧决策。输出必须是新目录；失败保留诊断及可能的未完成目录，不将其作为交付物，也不自动递归删除用户数据。

首版对同路径的 `event`、`map`、`msg`、纹理、配置等文件只提供完整文件选择；不承诺容器内部或脚本逻辑合并。如果用户需要双方在一个资源文件中的不同功能同时保留，当前选择机制不足，应报告具体资源及所需专用处理，不擅自选一方并称完成。

## 决策解释

报告至少包含稳定键、参数表/行/字段或文件路径、C/A/B 状态。可从本地 PARAMDEF 和 Mod 说明解释字段用途。没有依据的功能影响写为待验证；不要从字段名猜出确定的游戏行为。

用户可逐项选择，也可对明确集合给出统一策略。只有用户明确授权后才把该策略转成决策 JSON。选择 A/B 的含义是舍弃该冲突位置的另一来源变化；选择 C 的含义是保留基线状态。

## 验证层级

1. **输入证据**：基线来源、版本、原文件 SHA-256、工具程序集与参数定义身份可复核。
2. **参数结构**：加密文件可解密；BND/PARAM 可读取；重建参数与合并计划一致；没有因工具不支持而静默删表/删字段。
3. **文件产物**：普通文件和输出参数 SHA-256 与已选源一致；范围外文件没有被意外组装。
4. **功能效果**：只有实际运行双方功能并核验后才标为通过。无冲突和能读回均不能替代游戏测试。

本技能的自动关闭门覆盖前 3 层。第 4 层以“已测试/未测试”如实报告；当前排除动画、行为、HKS 与映射时，不能宣称依赖这些资源的动作功能已经兼容。
